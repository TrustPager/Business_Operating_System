# YouTube Thumbnail Studio

Standalone 1280×720 thumbnail studio for any kind of video you make, on your
own brand. Browser-based design editor at `localhost:3210`, puppeteer-based
PNG export, one-command upload to your workspace's Images folder.

The studio renders on the owner's brand, read from the root `brand/brand.json`,
so every thumbnail comes out in your own colours and wordmark. A walkthrough,
a story, a tips video — the studio serves any of them, not tutorials alone.

> **Framing note (supersedes the earlier TrustPager-tutorial framing).** This
> studio was originally built for the TrustPager tutorial channel: every
> title said "TrustPager" and every hero was a product-tutorial surface. That
> framing is now genericised to the owner's brand and any kind of video, per
> the YouTube Studio design doc Decision 9
> (`docs/architecture/2026-07-05-youtube-studio-design.md`). The distilled
> craft below (headline rules, the squint test, the thin-vertical-bleed hero
> rule, the banned-framing table) stays exactly as-is; only the
> brand-specific hard-rules and the tutorial-only assumption flip.

This studio ships as part of the [Business Operating System](../../README.md)
pack. The bundled sample designs show real thumbnails as design inspiration —
keep them, or wipe `src/data/samples.json` and start fresh with your own
designs via `npm run make`.

## Quick start

```bash
cd thumbnails
npm install
npm run dev                  # opens http://localhost:3210
```

In another terminal:

```bash
npm run make                 # interactive: add a new design
npm run shoot <key>          # render PNG + open it
npm run publish <key>        # render + upload to your workspace Images folder
npm run coverage             # which compositions are missing thumbnails?
```

## Linking thumbnails to Remotion compositions

Every thumbnail entry in `samples.json` carries a top-level **`composition`** field naming the Remotion composition it belongs to (e.g. `"composition": "Quote-Walkthrough"`), or `null` when the thumbnail isn't linked to a video project. That field is the single source of truth for the link.

Two ways to look it up:

- **From a composition** → open [`COMPOSITION_MAP.md`](COMPOSITION_MAP.md) and find the row. It lists every Remotion comp, whether it has a thumbnail, and which one.
- **From a thumbnail** → open `samples.json` and read the `composition` field (also shown under each entry in the studio sidebar at `localhost:3210`).

The map and the missing-thumbnail report are regenerated by:

```bash
npm run coverage
```

Run it after adding a new Remotion composition, or after a thumbnail render, to see the new state. The studio sidebar flags any entry that has no `composition` linked.

## What it produces

1280×720 PNGs in `output/`. A sample design is included as a reference.

The current canonical design:
- Flat white background, symmetric 28px margins
- The owner's wordmark at top-left (from `brand/brand.json`)
- Headline vertically centered on the left, one word in a teal→mint→blue gradient
- AI Activity hero card on the right (8–10 items, bleeds off the bottom edge)
- Soft color halos behind the hero card (left side stays clean white)
- Diagonal accent strip at the bottom

## The workflow

1. **Add a design** — `npm run make` walks you through it (key, headline, accent word).
2. **Iterate** — keep the dev server running and tweak `src/data/samples.json` or the template. Live reload.
3. **Render to PNG** — `npm run shoot <key>` runs puppeteer + real Chrome and opens the result.
4. **Publish** — `npm run publish <key>` renders again then uploads to the owner's workspace Images folder (when connected).

The studio's UI has click-to-copy chips for the shoot and publish commands so you don't have to remember the keys.

## Writing great thumbnails — what we learned

The two things that sink a thumbnail are a **weak title** or a **hero UI that screams "configurator"**. These rules are distilled from iterating on a full set of thumbnails (and many corrected drafts).

### Titles

**Format:** 4–7 words. One accent word that appears verbatim in the headline. Present-tense active verb. Use "AI" not "Claude" (wider audience).

**Lead with the outcome the viewer gets, not what the feature does.** The viewer is the beneficiary, not the AI.
- ✅ `Get AI to Fill Your CRM for You` — viewer is the beneficiary
- ❌ `AI Reads Your Notes, Fills the Deal` — AI is the subject; viewer is a bystander

**Specific outcomes beat airy abstractions.** If the outcome could just as easily describe a brochure, it's too soft.
- ✅ `See Exactly Where to Improve Your Business` (concrete benefit)
- ❌ `See Where Money Is Made` (cliché)
- ✅ `AI Builds Proposals for You` (specific verb)
- ❌ `AI Analyzes Your Deals in Seconds` (vague verb, mystery outcome)

**Never use scary, surveillance-flavoured, or accusatory framing.** Empowerment, not paranoia.
- ❌ `Track Every Promise You Make` (creepy, implies you'll fail one)
- ❌ `Know What Your AI Did Today` (vague accusation tone)
- ✅ `Watch Your AI Team Work Live` (empowering observation)
- ✅ `Ensure Your AI Asks Before It Acts` (active safety, not surveillance)

**Active and instructive beats passive and declarative.**
- ✅ `Make Sure Nothing Falls Through the Cracks` (you act)
- ❌ `Nothing Falls Through the Cracks` (just a vibe)
- ✅ `Never Type the Same Email Twice` (positive command)
- ❌ `Stop Typing the Same Email Twice` (negative framing — "stop" implies you're doing something wrong)

**Snappier is almost always better. Cut anything not load-bearing.**
- ✅ `Lock Down Your Data`
- ❌ `Lock Down What Each Person Sees`
- ✅ `Automate Everything`
- ❌ `Save Hours Every Week on Autopilot` (generic SaaS framing, no specific outcome)

**Cut the leading verb when the noun already carries the action.** Trust the noun. "Forms That Auto-Fill" already implies you're building/using them — the verb is dead weight. Same for "Notepads", "Tasks", "Emails", etc. Same for guarantor verbs like `Ensure` / `Make Sure` — the statement IS the guarantee.

| Verbose (bad) | Trimmed (good) |
|---|---|
| `Build Forms That Auto-Fill Your CRM` | `Forms That Auto-Fill Your CRM` |
| `Create Detailed Notepads for Every Deal` | `Detailed Notepads for Every Deal` |
| `Email Follow-ups That Send Themselves` | `Emails That Send Themselves` |
| `Ensure Your AI Asks Before It Acts` | `Your AI Asks Before It Acts` |
| `Make Sure Nothing Falls Through the Cracks` | `Manage Tasks with Ease` |
| `Watch Your AI Team Work Live` | `Watch Your AI Team Work` |
| `Run Sales and Service in One Pipeline` | `Sales and Service in One Place` |

**Steal punchy idioms over literal descriptions.** A common phrase the audience already knows ("Level Up", "One Place", "Inside Out", "Click of a Button", "Convert Forever") lands harder than a precise technical description. Borrow from gaming, sport, slang — the cultural shortcut does work for you.
- ✅ `See Where You Can Level Up` (gamer-coded; clear payoff)
- ❌ `See Exactly Where to Improve Your Business` (precise but flat)
- ✅ `Sales and Service in One Place` (folksy + concrete)
- ❌ `Run Sales and Service in One Pipeline` (technical and inert)
- ✅ `Know Every Client Inside Out` (idiomatic)
- ❌ `Recall Every Detail About Every Client` (catalogue-style)

**Drama and specificity create hooks.** Words like `Forever`, `Live`, `Auto-Fill`, `Click of a Button`, `Right From the CRM` give the title an edge.
- ✅ `Drip Campaigns That Convert Forever`
- ✅ `Close Deals at the Click of a Button`
- ✅ `Send Email Right From the CRM`
- ✅ `Build Forms That Auto-Fill Your CRM`

**The title must accurately describe the video.** Don't promise something the video doesn't deliver — viewers bounce in 5 seconds and the algorithm punishes you for it.

**Banned openings:** `Let`, `How to`, `Just`, `Stop X-ing`, `Tips for`, `Way to`.
**Stronger openings:** `Get`, `Watch`, `Make`, `Never`, `Build`, `Send`, `Close`, `Ensure`, `Run`, `Unify`, `Your <noun>`.

### Hero UI

#### The master rule: thin, tall, single vertical stack, bleeds off the bottom

The hero card is **528px wide × ~720+px tall**, taller than wide, with content running off the bottom edge of the 1280×720 canvas. Every hero is a **single vertical stream of feature-specific items** — no horizontal subdivisions, no side-by-side columns, no two-up grids inside the card. The bleed-off-bottom is what tells the viewer "this goes on forever — the feature has depth".

The original AI Activity card had the right *form* (thin / vertical / stacked / bleeds). It had the wrong *content* (generic agent text rows that fail at YouTube scale). Every hero from now on keeps that form, swaps in feature-specific iconic items.

#### One outer container, panels inside

Every hero is a **single outer white card** with the heavy shadow (`0 26px 52px rgba(15,17,23,0.12)` etc.) and a `borderRadius: 18` and an internal padding of ~18px. The feature-specific items (chat bubbles, deal cards, chart panels, booking rows) stack INSIDE that container. The outer container is what gives the hero a sense of being *on a page* rather than a pile of floating tiles.

If your hero is more than one root element, it's wrong. Open the existing heroes — `SmsHero`, `PipelineHero`, `SchedulingHero`, `ReportsHero` — they all share the same outer-container chrome.

Inner panels (chart cards, booking rows) get a **light border** (`1px solid rgba(226,232,240,0.7)`) — NOT their own heavy shadows. The heavy shadow lives on the outer container only. Stacked light borders read as "sections of one dashboard"; stacked heavy shadows read as "four floating cards".

#### Squint test (the deal-breaker)

View the rendered PNG at **25% zoom**. If you can't tell what the video is about from shapes and colours alone — no reading required — the hero fails. YouTube serves thumbnails at ~480×270 desktop, 246×138 mobile. Text becomes a grey smear at that size; only shape, colour, and silhouette survive.

#### The iconic silhouette per topic

Every feature has a recognisable vertical shape. Stack items in that shape's language.

| Topic | Vertical stack of… |
|---|---|
| Scheduling | Date headers + event blocks (time + name + duration) |
| Service Request | Completed-request cards (✅ "Shipped" + tiny feature preview) |
| Google Calendar | Upcoming-event rows (time + title + source badge) |
| Forms | Field stack — labels + inputs + checkboxes, one mid-AI-fill |
| Needs Analysis | AI-generated sections (Exec Summary → Need cards → Pricing) |
| Notepads | Notepad cards (folder tag + title + first line + last edited) |
| Permissions | Role cards (role name + scope count + shield) |
| Pipeline | Deal cards under a single coloured stage header |
| Reports | Chart cards stacked (donut → bars → trend line) |
| SMS | Chat thread — bubbles alternating left/right |
| Automations | Action cards in a flow (Send Email → Create Task → Send SMS) |
| Tasks | Checklist items (status pill + title + due + assignee) |
| Agent Hub | Agent cards (avatar + name + status pulse + capabilities) |
| Approvals | Approval cards (request title + Approve/Reject button row) |
| Stage emails | Triggered-email log entries (deal stage moved → email sent) |
| Contacts | Contact cards (avatar + name + employer chip + recent activity) |
| CRM Templates | Template cards (subject + body preview with `{{merge}}` chips) |
| Proposals & Documents | Document-page silhouettes (cover → pricing → signature) |
| Send & Track Emails | Inbox rows (sender avatar + subject + tracked badge) |
| E-Signing | Signed-contract cards (✓ stamp + signer + timestamp) |
| Event Queues | Timeline rows (Day 1 → Day 3 → Day 7 with action icons) |
| Fill with AI | Field rows mid-auto-fill, sparkle/wand on the active row |

#### Show the outcome, not the configurator

| Mechanism (bad) | Outcome (good) |
|---|---|
| Form Builder editor | Stack of "form filled the CRM" events with auto-populated fields |
| Approvals queue full of "Pending" rows | Stack of approved cards w/ ✅ "AI sent the email" underneath |
| Stage-automation config modal | Stack of stage-change events that triggered emails |
| Document editor with sections sidebar | Stack of finished proposal-page thumbnails |
| Empty event-queue config screen | Stack of "Day N: action fired" log rows |
| Service Request submit modal | Stack of completed request cards w/ ✅ "Live on your account" |

#### Density of shape > density of text

A hero packed with **coloured shapes** (status pills, avatars, chart slices, stage badges, signature stamps) survives shrinking. A hero packed with text rows dissolves. When in doubt: **fewer items, bigger shapes, stronger colour contrast.**

#### Caricature beats realism

If a faithful product render makes the hero illegible at thumbnail scale, exaggerate the iconic elements. Bigger avatars. Fewer items but each one larger. Bolder colour anchors. The hero is a *miniature*, not a *screenshot*.

#### Every hero needs a colour anchor

Each hero must have at least 2-3 brand-coloured shapes (teal/green/blue pills, headers, chart slices, status dots, signature stamps) that survive at 25% zoom. A pure-white card with text-only content fails the squint test.

#### Use brand colours only

Real product UI uses orange, purple, red in places. **Heroes don't.** Map them to brand teal / blue / green / slate. See the palette section in [`src/templates/YouTubeThumbnail.jsx`](src/templates/YouTubeThumbnail.jsx).

#### Halos behind the hero only

Teal/mint/blue colour blooms sit behind the right-side card. The left side stays pure flat white so the logo + headline read cleanly. Mask the halo so it fades before reaching the text.

#### Differentiate visually similar topics

Pipeline (#8) and Stage-emails (#15) both live in pipeline-card-stack territory. Differentiator: #8 = deal cards under a stage header, #15 = stage-change *events* with email-sent icons. The silhouette must be visibly distinct at thumbnail size.

#### Don't lead with security/gatekeeping vibes

The Permissions thumbnail's first instinct was a dense scope matrix — that reads as bureaucratic. Reframed to a stack of role cards with shield icons + "Protecting N resources" pills. Same topic, opposite vibe.

## Hero registry — per-topic UI cards

Every thumbnail's right-side hero is a **dedicated component** matched to that video's product surface. They live in [`src/templates/heroes/`](src/templates/heroes/) and are wired up through [`heroes/index.js`](src/templates/heroes/index.js).

```js
// src/templates/heroes/index.js
export const HEROES = {
  'pipeline':     PipelineHero,      // kanban column with deal cards
  'sms':          SmsHero,            // chat thread with AI bubbles
  'reports':      ReportsHero,        // stat + donut + trend + bars
  'scheduling':   SchedulingHero,     // day-grouped agenda
  'permissions':  PermissionsHero,    // scope matrix grid
  'notepads':     NotepadsHero,       // one rich polished notepad
  …
};
```

Each samples.json entry references its hero by key:

```json
"pipeline": {
  "data": {
    "headline":   "Sales and Service in One Place",
    "accentWord": "One Place",
    "hero":       "pipeline",
    "title":      "How I Run Sales and Service From One Place"
  }
}
```

### The six family patterns

When you add a new video topic, pick the existing pattern that best fits what the video is about and copy from the closest existing hero:

| Pattern | Examples | When to use |
|---|---|---|
| **Card stack** | service-request, contacts, approvals, esigning, notepads (preview list) | Discrete records, each a self-contained card |
| **Event/log row** | google-calendar, send-emails, stage-emails, event-queues | Timestamped events flowing down a feed |
| **Field stack** | forms, fill-with-ai | Field/value pairs, some mid-auto-fill |
| **Roster** | permissions, agent-hub | A list of role/agent identities with metadata |
| **Checklist** | tasks | Items with state pills (✓ / ⏳ / ◯) |
| **Document** | proposals, needs-analysis, notepads (rich), crm-templates | A single polished doc rendered top-to-bottom |
| **Flow** | automations | Trigger → action cards connected by arrows |

### The "one polished thing vs many previews" decision

- If the topic is **a single artefact** the user produces (a proposal, a notepad, a needs-analysis) → show ONE polished version of that artefact rendered top-to-bottom inside the hero. NotepadsHero does this.
- If the topic is **a directory of things** (contacts, templates, agents, approvals) → show a vertical stack of compact preview cards.

ServiceRequestHero is interesting because it's both: each request card has its own contained mini-state, but the value of the feature is the stack of completed deliveries.

### Build a new hero

```bash
# 1. Pick a pattern + open the closest existing hero as a template
cp src/templates/heroes/PipelineHero.jsx src/templates/heroes/MyTopicHero.jsx

# 2. Edit MyTopicHero.jsx — change the data, swap the silhouette
# 3. Register in heroes/index.js:
#    import { MyTopicHero } from './MyTopicHero.jsx';
#    'my-topic': MyTopicHero,
# 4. Reference it from samples.json:
#    "my-topic": { "data": { ..., "hero": "my-topic" } }
# 5. npm run shoot my-topic to verify
```

**Every hero must follow the master rules:**

- Single outer white card with the heavy shadow + `borderRadius: 18` + ~18px padding
- Thin / tall / single vertical stack — no horizontal subdivisions
- Content bleeds off the bottom of the canvas (~6-10 items needed)
- Inner panels get a `1px solid rgba(226,232,240,0.7)` border, NOT their own shadow
- Brand colours only (`#29c6c6`, `#2db87d`, `#47a3d9`, `#7dd3d3`, `#1ea5a5`, `#94a3b8`) — no orange / purple / red in chrome
- Pass the **squint test** at 25% zoom — the silhouette must communicate the topic without reading

The full rule set with examples is in [`heroes/index.js`](src/templates/heroes/index.js) and the JSDoc at the top of [`templates/YouTubeThumbnail.jsx`](src/templates/YouTubeThumbnail.jsx).

## Avatar system

Two pools of real images. **Always prefer real avatars over initial-letter coloured divs** — at thumbnail scale, initials read as generic chips; real portraits read as humans.

### People avatars — `src/profiles.jsx`

Five real portraits served from a CDN you configure (`IMG_BASE` in `profiles.jsx`), hashed by name so the same fictional person always wears the same face:

```jsx
import { Avatar } from '../../profiles.jsx';

// In any hero
<Avatar name="Saskia Williams" size={32} />
<Avatar name="Hugo Daniels" size={28} style={{ boxShadow: '0 1px 3px rgba(15,17,23,0.15)' }} />
```

### AI agent avatars — `public/agents/<Name>.png`

Eight AI-agent portraits (Aria / Marty / Mira / Lyra / Orion / Sable / Echo / Custom) ship under `public/agents/`. Reference them directly:

```jsx
<img src="/agents/Aria.png" alt="Aria" style={{ width: 46, height: 46, borderRadius: '50%' }} />
```

To add new agents, just `Copy-Item` the new PNG into [`public/agents/`](public/agents/).

**Brand rule on agents:** keep the surrounding chrome (status pills, role tags, capability badges) on the owner's brand palette, read from the root `brand/brand.json`. The agent portraits themselves stay full-colour — they're the identity. If a source screenshot brands something in an off-palette colour (purple / orange / red), remap that chrome to the owner's brand colours in the thumbnail.

## Output filenames match YouTube titles

The `title` field in each samples.json entry is the exact YouTube video title. `render.js` / `shoot.js` / `publish.js` all use that title (sanitized for Windows-illegal chars) as the output filename — so the rendered PNG drag-drops straight onto the YouTube upload page with no renaming.

```
output/
├── How I Quote a Job in Under a Minute.png
├── The Fastest Way to Follow Up After a Site Visit.png
├── What Changed When I Started Quoting on the Spot.png
└── …
```

If the `title` field is missing, the script falls back to the short kebab-case key.

## Where the design system lives

The `SYS` constants block at the top of [`src/templates/YouTubeThumbnail.jsx`](src/templates/YouTubeThumbnail.jsx) controls every spatial measurement (margins, gap, column widths, padding, font sizes, border radii). Bump `margin: 28` to 36 and the whole composition breathes wider. Do NOT hard-code positions elsewhere.

The headline gets a stacked white `drop-shadow()` filter so it stays legible where it overlaps the hero card — invisible against the flat white left side, kicks in only where the headline runs into coloured content on the right.

## Adding a new design

End-to-end walkthrough for adding a fresh thumbnail:

### 1. Decide the headline + accent

Apply the title rules above. Cut leading verbs. Steal punchy idioms. Pick a single accent word (or a 2-word phrase) that appears verbatim in the headline.

### 2. Pick or build the hero

- Decide the iconic visual centrepiece that carries what the video is about. A walkthrough picks the product surface it covers; a story or a tips video picks the shape that best carries its idea.
- Pick a [family pattern](#the-six-family-patterns) that fits.
- If an existing hero is close enough, reuse its key. Otherwise build a new component in [`src/templates/heroes/`](src/templates/heroes/), register it in [`heroes/index.js`](src/templates/heroes/index.js).

### 3. Add the entry to samples.json

```json
"my-topic": {
  "template":    "youtube-thumbnail",
  "composition": null,
  "data": {
    "headline":   "Punchy 4-7 Word Title",
    "accentWord": "Word",
    "hero":       "my-topic",
    "title":      "How I <Verb> <Thing>"
  }
}
```

The `composition` field is optional: set it to the Remotion comp id from `src/compositions/*.tsx` (look for `<Composition id="...">`) when the thumbnail belongs to a linked video project, or leave it `null`. When set, it's what `npm run coverage` cross-references to flag missing thumbnails.

### 4. Render and verify

```bash
npm run dev                    # if not already running
npm run shoot my-topic         # renders + auto-opens the PNG
```

**Always READ the PNG.** The studio preview can differ from the puppeteer output. Zoom out to ~25% in the image viewer and squint — the silhouette must communicate the topic without reading.

### 5. Publish

```bash
npm run publish my-topic
```

Uploads to your workspace Images folder → the "YouTube Thumbnails" folder, with the YouTube title as the filename.

## Publishing

```bash
npm run publish <key>                  # one design — skip if a file with that name already exists
npm run publish -- --all               # every design — skip existing
npm run publish <key> --replace        # delete the existing file then re-upload (one)
npm run publish -- --all --replace     # wipe + re-upload everything
```

**Default behavior is idempotent.** Before uploading, `publish.js` lists the existing files in the "YouTube Thumbnails" folder and skips any whose name already exists. First run uploads everything; subsequent runs are no-ops unless you've added a new entry to `samples.json`.

**`--replace`** is for genuine updates — when you've re-rendered a thumbnail and need the live version replaced. It deletes the existing file before uploading the new one.

Targets:
- **Workspace:** your own workspace (the publish driver targets a TrustPager workspace via its API)
- **Folder:** "YouTube Thumbnails" (in the Images category)
- **API key:** set `TRUSTPAGER_API_KEY` in your environment (or use the standard `~/.claude/bos.json` config that `tools/setup.py` writes)

Files land in your workspace Images area inside the "YouTube Thumbnails" folder, named by their YouTube title (e.g. `How I Quote a Job in Under a Minute.png`).

## Troubleshooting

- **Studio preview shows gradient correctly but PNG looks broken** — don't use a browser-side download library. The puppeteer export (`npm run shoot`) is the canonical render. The in-studio top-bar shows command chips, not a Download button.
- **Publish landed but doesn't show on `/content/images`** — check that `category: "images"` is being passed in the upload body (publish.js handles this; if you're calling the API directly, that field is required).
- **Headline wraps weirdly** — adjust `SYS.leftColWidth` in the template. The default is 620; for very long words try 680.
- **Halos showing on the left side** — they shouldn't. ColorHalo's mask gradient should fade left-to-right (so right side has the bloom, left side stays white).
