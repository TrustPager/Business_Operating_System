## Increment 1 — Cold-install self-sufficiency (D11) + the README front door  [SHIP-BLOCKER #1]

### Task 1.1 — Bundle + self-heal the document dependency stack
**The problem (hit 6/10):** on a fresh machine the BOS can WRITE a `.docx` but can't READ one (markitdown core lacks the `[docx]`/`[pdf]`/`[xlsx]` extras); `markitdown_convert.py` exits 0 on failure; `openpyxl` had an interpreter mismatch; the install hints say bare `pip install` (a churn trap on multi-Python Windows).
**Build (per D11 — bundle, then detect → offer → do-on-yes → verify):**
- **Bundle** the always-needed libs in `tools/setup.py` (and a `requirements.txt`/declared deps): `python-docx`, `openpyxl`, `pdfplumber`, `reportlab`, and `markitdown[all]` (or at least `[docx,pdf,xlsx,pptx]`). A normal install should need zero manual steps.
- **Tools emit a machine-readable missing-dep signal:** every doc tool (`markitdown_convert.py`, `write_xlsx.py`, `write_docx.py`, `make_pdf.py`, `pdf_tables.py`) on a missing import prints a structured line (e.g. `BOS_MISSING_DEP: <pip-name>`), recommends `python -m pip install <name>` (NOT bare `pip`), and **exits non-zero**. `markitdown_convert.py` must catch the per-format `MissingDependencyException` (not just total `ImportError`) and name the exact extra (`markitdown[docx]` etc.).
- **`check-install.py` keyless-floor mode (make it the default):** verify the document stack with a real **write→read round-trip** (write a tiny `.docx`/`.xlsx`, read it back via markitdown), report each missing dep, and support a `--fix` that installs the missing deps via `sys.executable -m pip install`. The existing TrustPager probes move behind a "if a CRM is connected" branch — the doctor must serve the keyless floor first.
- **Skill-layer behaviour (the offer):** add to the document-tool method doc + the relevant skills the D11 loop — when a tool reports a missing dep, the assistant says "to do this I need to add X; want me to set that up?" and on yes runs `python -m pip install X` itself, then retries. Never instruct the owner to run it.
- **Knowledge file:** `knowledge/setup-and-dependencies.md` — plain-language: what the system may need, that the BOS installs it for you with your OK, and the (rare) manual fallback.
**Acceptance:** on a machine missing the extras, a doc round-trip either works (bundled) or the assistant offers + installs + succeeds without the owner touching a command; tools exit non-zero on real failure; `check-install.py --fix` heals a fresh install; lint/binding/offline green.
